# 按主体与剧情节点恢复知识

这套库是可核查的参考资料。`records.json`包含全书真相，**不能整份注入某个NPC或User**。

1. 先确定CH身份和EV节点，并说明在事件前还是事件后。尚未选择RP开局；本阶段没有代选日期。
2. 只取该主体的T节点。正文客观层、读者揭示、别人的知识与组织文件都不自动进入。
3. 当代节点按原文中实际获取的子段排序；回忆先判断故事发生期。EV号、K号、章节出现顺序均不是全局日历。
4. 保留原认知状态。HEARD只允许说“听到过”；SUSPECTS只许猜；PARTIAL只许已列片段；MISUNDERSTANDS允许角色保有错误解释，不能悄悄替换正确答案。
5. 同一命题读取当前已发生的最新有据认知。若偏序不足以比较两个状态，返回待核，不猜一个。瞬时敌情、当时安全、旧伤诊断须保留发生期，不能当如今事实。
6. UNKNOWN不等UNAWARE。前者是无法判断知情；后者需要实际隐瞒/缺席/误会等证据。两者都不允许用客观层填空。
7. 单独核对披露边。持有知识不等已经告诉对方，允许披露不等实际已披露；向一位队友披露不等向全队同步。
8. 群体只限本次实际接触的集合。未具名成员不自动映射组织全员；公告时间只代表可接触，不等每个人已接收。
9. 田胜的记忆缺口、红的禁想遗忘、白的失真回忆分别处理。不能因为事件库保留原经历，就补回角色实际没有的完整记忆。
10. 已故安雅没有死后获取节点。生前自知家庭身份不等死后知道女儿经历、同伴阴谋和后期战争解释。

## 只读辅助查询

```powershell
python canon/knowledge/query_knowledge.py --character CH003 --event EV0036
python canon/knowledge/query_knowledge.py --character CH007 --event EV0082 --before
```

输出仅含该主体已获授权的限定内容，以及被拦截的未知/遗忘记录。**不输出客观真值，不复制完整原文段落，不自动读取G/ORG群体权限。** 这不是SillyTavern实现或已经完成实机验证。

历史采用已证偏序，无法排列的跨度宁可返回少量状态。任意EV可查询，但复杂历史内部节点、并行战斗中的具体瞬间和公告收听人员仍需按T证据窗口复核。这一保守限制不代表尚未记录的知识在原著中必定不存在。

同一事件涵盖多个子场景时，`--before/after`只表示整个EV窗口之前/之后。要在事件中间开局，应人工使用主档的源行与`within_event_sequence`选节点；不要把整件事件后的状态放到中段。

## 重要例子

- 夏凉：同一身份确认与性别来源理解是两条命题。她可以正确知道林昀＝翠雀，同时保留错误方向解释。
- 小璐与白静萱：同生日、妈妈爸爸称呼、母亲是樱，均不能解锁男翠同一。
- 土丁桂与狗尾草：末场前只解锁龙胆→翠雀→矢车菊少女代号链；不给林昀男身。
- 翠雀：确认墨的团队和爪痕有关，不等在缺席密谈时就知道黑猫代号。
- 玛格丽特：葬礼前已经知道安雅死；当代墓园是向林解释消息来源，不能当本人首次获死讯。
- 苏胜紫：历史苏→玛的通话，与当代玛→林/红的转述分别成立；没有到达、入伙或死亡确认。

## 证据与使用权限

来源A–F沿用上游政策。A可以证明说话行为，D保留说法内容，F表示未证。单页客观层的证据窗口是检索导航，不声称这一窗口的每个字都支持整个命题或都被NPC听见。

User必须另有身份、时间点和经历。用户裁决允许的IF只由后续设计层记录，不在本库伪装成原著早已坦白。源文最终止于繁开唱名，结局与未披露秘密继续封锁。
