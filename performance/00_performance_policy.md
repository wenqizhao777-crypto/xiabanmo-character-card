# Performance Policy｜Stage 3A 人物可演绎模型规则

## 0. 本层是什么

`performance/` 是 **Canon 的解释层与执行层**，不是事实层。

- 事实来源永远是 `canon/`（`CANON_BASELINE_V1 = FROZEN`）与 `source/` 原著正文。
- 本层做的事：把已冻结的事实、行为证据、关系阶段、知识边界，翻译成"这个人在新场景里会怎么判断、怎么说、说到哪一步、不做什么"。
- 本层不做的事：产生任何新的原著事实。

**冲突处理规则：若本层任何一句解释与 Canon 冲突，改本层，不改 Canon。**

任何下游（世界书、角色卡、游戏系统）引用本层内容时，必须知道它读到的是"可演绎模型"，不是"原著写过"。凡下游需要断言"原著里发生过 X"，必须回 `canon/` 或 `source/` 取，不得引用 `performance/`。

## 1. 目录与写入边界

```text
performance/
├─ README.md                 进度表与 Tier A 索引
├─ 00_performance_policy.md  本文件
├─ tier_a/                   每人一份 Performance Model
├─ validation/               每人验证记录
└─ STAGE3A_REVIEW.md         本阶段 Review
```

**只写 `performance/`。** 本阶段禁止写入或修改 `canon/`、`audit/`、`current/`、`final/`、`source/`、`prototype/`。

## 2. 标记系统

每条实质判断必须带一个来源标记。标记写在句首方括号内。

|标记|含义|可靠度|下游可否当事实用|
|---|---|---|---|
|`CANON_DIRECT`|Canon 记录里直接写明的事实或行为（可指到 CH/REL/K/EV/源行）|与 Canon 同级|可，但应回引 Canon 原条目|
|`CANON_PATTERN`|**多个独立 Canon 证据**支持的重复行为规律|高|作为倾向使用，不作为单次必然|
|`INTERPRETIVE_MODEL`|本层对 Canon 的心理/行为解释，用于填补新场景|仅本层|**否**|
|`STAGE_BOUND`|只在某剧情阶段成立，换阶段即失效|视阶段|必须带阶段读|
|`RELATIONSHIP_BOUND`|只对特定关系对象成立|视对象|必须带对象读|
|`CONTEXT_BOUND`|只在特定情境条件下成立（战场／公务／私下／有第三人在场等）|视情境|必须带条件读|
|`UNKNOWN`|Canon 没写，本层也不补|—|否，且不得脑补|

组合标记允许，例如 `[CANON_PATTERN｜STAGE_BOUND]`。

### 2.1 硬规则

1. **`INTERPRETIVE_MODEL` 永远不得反写 Canon。** 它不能被下游升级成 `CANON_DIRECT`，不能进入世界书的"设定"区，只能进入"演绎指引"区。
2. **`CANON_PATTERN` 的门槛是多个独立证据。** 原著做过一次 ≠ 高频行为。单次行为写成 `CANON_DIRECT` 并保留情境限制，不得泛化。
3. **`UNKNOWN` 不得被补成事实**，也不得被"合理推测"悄悄换成 `INTERPRETIVE_MODEL` 然后当事实用。本层允许对 UNKNOWN 提出"若发生，可能走向 A 或 B"，但必须并列写、标为分歧，且不得写进 RP 执行摘要的断言句。
4. **认知 CONFIRMED ≠ 命题为真。** 人物确信某事，只说明他会按此行动；该命题本身的真值另查 K 记录的 `truth`。演绎时用人物的认知，不用世界的真值。
5. **禁止外部人格框架替代原著。** 不使用 MBTI、九型、依恋类型分类、精神医学诊断名词作为人物结构骨架。可以描述行为（"回避冲突话题"），不可以贴标签（"回避型依恋"）。
6. **禁止为戏剧性新增。** 不新增创伤、秘密、恋爱、执念、疾病、亲属。
7. **禁止未来知识前置。** 建模只能用该人物在所处阶段已获得的 Knowledge；读者已知不等于人物已知。

## 3. 稳定人格 vs 阶段状态

每条人格判断必须能回答："这是 `STABLE` 还是 `STAGE_BOUND`？"

- `STABLE`：跨多个阶段、多种情境反复出现，且没有明确的起始外因。
- `STAGE_BOUND`：由某事件、某伤势、某身份、某时期产生，并会随阶段改变。

**特别禁止**：把某阶段的抑郁、疲惫、暴躁、戒备、依赖、伤痛、爱慕、敌意冻结成永久人格。丧失、受控、重伤、被识破、刚失去队友这类状态一律默认 `STAGE_BOUND`，除非 Canon 显示它跨阶段持续。

## 4. 关系差分原则

人物面对不同对象**不能只换称呼**。差分至少覆盖：默认态度、信任方式、边界、更容易/更不愿表现的情绪、会主动做什么、通常不会主动做什么、冲突处理方式、阶段变化。

- 有向关系：A→B 与 B→A 是两条边，可以不对称。喜欢不等于双方恋爱。
- 关系类别按 Canon REL 的 `categories` 走，不自造类别。
- 关系升级需要 Canon 事件支持。**RP 过程中的互动不能反写 Canon 关系**，只能在 RP 会话内产生临时状态。

## 5. Knowledge / Disclosure 执行原则

**知道 ≠ 愿意说。** 每个人物必须把知识分成七档：

1. 可自然谈论
2. 知道但通常不主动说
3. 明确保密（有承诺、有职责或有风险）
4. 部分知道
5. 怀疑未确认
6. 错误认知（人物相信但不为真——按人物的错误认知演，不悄悄纠正）
7. 当前阶段完全不知道

披露判断按：对象关系 → 是否有保密承诺 → 组织职责 → 泄露风险 → 当前压力状态。同队、同城、同机构、同组织**都不等于共享信息**。

## 6. User 原则

**User 不是特殊关系类别。**

除非 User 被明确绑定到某个 Canon 身份／关系，否则自由 OC 在初见时只能按：当前剧情节点 → User 的身份与所属组织 → User 的实际行为 → 已发生的互动，动态建立关系。

禁止默认：关注 User、信任 User、对 User 泄密、被 User 吸引、把 User 排在原著关系之上。

人物必须保有独立目标：在 User 不在场时他也在做事；在 User 提出请求时他会先按自己的优先级判断。

## 7. 亲密关系防快餐化

只有 Canon REL 中存在爱慕／恋爱维度的人物才做亲密建模，且必须写清：亲近条件、接受亲密的条件、拒绝或犹豫的方式、表达喜欢的方式、主动性程度、会降低信任的因素。

- 禁止"好感值够了就恋爱"。
- 家庭称呼、家庭认同、情感承诺、法律关系、血缘：五层分开，不互相推导。承诺照护 ≠ 收养手续；叫"妈妈" ≠ 法律亲子；血缘 ≠ 身份已公开。

## 8. 互动节奏原则（防 NPC 独占剧情）

每个人物必须标注五档主动性：**会主动做 / 需要触发 / 被要求后可能做 / 通常拒绝 / 极少才做**。

系统性防止：一次发言十段、一回合做五件事、替 User 决定、独自把剧情推完、连续自我剖白。

## 9. Novel Situation Protocol（新场景推演顺序）

原著没有直接答案时，按此顺序判断，不得跳步：

1. 当前 Canon 剧情节点（在哪个阶段）
2. 身份／职务／能力／伤势的当前状态
3. Knowledge（此刻他知道什么、不知道什么、错认什么）
4. Relationship（对在场每个人的有向关系与阶段）
5. 心理阶段状态（`STAGE_BOUND` 项是否正在生效）
6. 核心价值优先级
7. 可重复行为模式（`CANON_PATTERN`）
8. 当前风险评估
9. 生成行动

若多种反应都合理：写**高概率反应 / 次可能反应 / 分歧条件**三项，不伪装唯一答案。

## 10. 验证要求

每个人物完成后至少三类测试，结果写入 `performance/validation/`：

- **Canon Scene Reconstruction**：取原著已有场景，只给模型该场景之前的状态，看模型预测的反应是否与原著大体一致。不一致要记录是模型错还是场景另有条件。
- **Novel Scene Generalization**：设计原著未发生、且不改变任何 Canon 的低风险新场景，检查模型能否自然推演而不脑补事实。
- **Adversarial OOC Test**：陌生 User 突然示爱 / 追问秘密 / 要求违背职责 / 高压冲突 / 被误解 / 被拒绝 / 亲密推进过快 / 未来信息诱导。检查是否守住关系、Knowledge 与人格边界。

## 11. 反模板化要求

十个人不得共用同一套：心理防御方式、对话节奏、"嘴硬心软"叙事、自嘲习惯、压力下沉默、对 User 慢热但最终恋爱。

每人必须写 **Anti-Flattening** 一节：说明本人最容易被简化成哪个标签、为什么该标签不够、保留哪些内部张力。

## 12. 引用与证据追踪

每份模型末尾列出支撑证据：CH／REL／K／EV，必要时给源行区间。

**`INTERPRETIVE_MODEL` 必须可追溯到具体依据**（哪条 Canon 行为让你这样解释）。不能追溯的解释删掉，不留在文件里。

引用原著时给行号定位与简述，不整段誊抄台词。

## 13. 发现 Canon 疑点时

不得修改 `canon/`。在 `STAGE3A_REVIEW.md` 建立 `CANON_REVIEW_REQUEST` 条目，记录：涉及 ID、当前 Canon 写法、发现内容、原著证据位置、影响范围、建议。交由后续受控复核处理。

## 14. 本阶段禁止清单

修改 `canon/` / `audit/` / `current/`；写入 `final/`；重写角色卡；生成世界书条目；修改骰子／CG／好感系统；给人物补恋爱／补创伤／补秘密；默认 User 特殊；把心理解释写成 Canon；用外部人格框架替代原著人物；为文艺感过度心理化；大量复制原著台词。
